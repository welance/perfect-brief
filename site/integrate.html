the mcp server, step by step

Your assistant, holding a bar it cannot bend.

1

Install nothing: uvx fetches and runs it. You need uv (or use pipx).

2

Add this to your assistant's MCP configuration — Claude Desktop, Claude Code, Cursor, or anything else that speaks MCP.

json · configuration
{
  "mcpServers": {
    "perfect-brief": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/welance/perfect-brief#subdirectory=mcp-server", "perfect-brief-mcp"]
    }
  }
}
3

Ask it to score a brief. It will read the rules first, report the decision, and fix the gate before anything else — that order is built into the server's own prompt.

Optional: set PB_LLM_KEY to your own OpenRouter key and the judge runs on your account — we forward the call and run no model for you. See your brief, your key for exactly what travels where.

or just call it
curl -X POST https://briefs.welance.com/v1/score \
  -H 'content-type: application/json' \
  -d '{"brief":"…","judge":"llm"}'
const res = await fetch("https://briefs.welance.com/v1/score", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ brief, judge: "llm" }),
});
const { score, decision, gate } = await res.json();
import httpx

r = httpx.post("https://briefs.welance.com/v1/score",
               json={"brief": brief, "judge": "llm"})
score, decision = r.json()["score"], r.json()["decision"]

Read the bar first with GET /v1/rules, or point a machine at llms.txt. Full reference in the API docs.

before you build on it

It scores articulation, not truth.

A brilliantly written brief for a doomed product will score well. What the bar gives you is narrower and more useful than a verdict on your idea: a number two people get the same way, a gate that refuses on policy rather than taste, and a shared vocabulary — "success-metrics is failing, weight 10" beats "the AI thinks it could be better". Build on that, not on the promise of good judgement.
